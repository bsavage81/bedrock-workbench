## Architecture and stopping points

The shared content index and molang-bindings view already enforce owner/subpack context. candidates() resolves compatible project/vanilla geometry/textures and infer() uses the owned Molang lexer/parser with bounded substitutions. preview-plan groups alternatives per controller and preserves independent controller declaration order. sendAutomatic rebuilds that plan and sends all resolved passes to WebGL. This is already more than a controller selector refresh.

Remaining gaps: predicates lack &&/|| and have unary/comparison precedence problems. Unknown activation dependencies disappear when an inactive branch is skipped. Material expressions remain raw aliases in the renderer-facing stage, and material/visibility dependencies are not fully collected by inference. Secondary samplers use find(), allowing duplicates to win by file order. Plan diagnostics are strings and lack explicit per-controller resolved/ambiguous/unknown outcomes. Geometry/material/visibility/provenance resolution remains split between plan and sendAutomatic. Unknown visibility is deliberately shown with warnings; no arbitrary runtime values are assumed.

The UI exposes model/texture selectors and a manual-inspection checkbox alongside property/controller choices. Appearance/Layers/Inspect modes, layer isolation, richer expression/provenance inspection and reliable presets are absent. WebGL groups bones by material profile; two-sampler composition and profile approximations already exist, but this audit does not establish masked shader parity or visual correctness. TGA/UV/camera behavior must remain intact.
