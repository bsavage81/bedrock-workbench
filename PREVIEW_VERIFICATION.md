## 0.26.1 UV and rotation correction

The user's cow screenshot exposed errors the first milestone's visual checks and UV-rectangle tests missed. The converter had mixed Bedrock coordinates with ordinary right-handed rotations and assigned east/west atlas strips and top/bottom UV endpoints incorrectly. Earlier loading/appearance checks did not establish accurate corner mapping.

The converter now reflects Bedrock X positions and pivots into one right-handed renderer space, converts Euler angles to `[-X, -Y, Z]`, and applies rotations X then Y then Z for both cubes and parent bones. Box UVs use the correct side strips and signed top/bottom rectangles. Explicit top/bottom face UVs reverse both endpoints, including signed UV sizes. Mirror swaps the two side strips and reverses U; an explicit cube mirror setting overrides the bone setting.

Verification: syntax checks and all 13 preview tests pass; full suite 257 tests, 256 passed, one skipped, zero failures. New tests assert asymmetric atlas corners against scene corners on all six faces, signed per-face top/bottom orientation, mirrored strip routing and overrides, the cow neck's forward lean, and combined cube/parent/grandparent pivots. They fail the old conversion conventions rather than merely checking that data loaded.

Native VS Code 1.143.1 correction-host inspection used unmodified copies of SavageCraft `cow.v2.geo.json` and `cow_v2.png`, with an isolated single-binding owner. The 192×192 image uses the model's 96×96 UV space. Checked the tucked neck, muzzle/eyes, yellow ear tag, top/side patch continuity, orbiting and camera reset. No pack sources were edited. Geometry SHA-256: `edbd7fe6347253296801c317f356ae4b166fb2c402d4ffccf5e48cb7a065adb8`; texture SHA-256: `28371335d51e0fde9e46a958f6332f6d9000f2e2b684900ceb61ea9aa5815f0d`.

The reference behavior was cross-checked against [Blockbench's tagged Bedrock importer](https://github.com/JannisX11/blockbench/blob/v4.12.6/js/io/formats/bedrock.js) and [face/box UV definitions](https://github.com/JannisX11/blockbench/blob/v4.12.6/js/outliner/cube.js), alongside the Microsoft geometry documentation below. The fix is the Workbench converter's coordinate/UV mathematics; no Blockbench runtime or source module is bundled. ## Rendering choices and limits

An extension-owned dependency-free WebGL renderer receives only geometry data and selected image data URLs. Webview file roots allow the extension media directory only; workspace paths never come from webview messages. Assets must resolve inside configured pack roots or an approved vanilla source/cache inventory and be at most 16 MiB. Trust is checked before opening, scanning and sending assets. No webview network access, eval, project scripts or runtime Molang evaluation; the host may fetch compatible pinned Mojang resources as described above.

Static modern/legacy cube geometry supports parent pivots/rotations, cube pivots/rotations, inflation, box UV mirroring, per-face UV rectangles and signed UV sizes. Texture UV normalization uses declared geometry dimensions, independent of PNG resolution. Texture sampling uses NEAREST and clamp-to-edge without mipmaps, including non-power-of-two dimensions. Orthographic orbit/pan/zoom camera; reset restores a fitted view. Unlit double-sided surfaces, depth testing, alpha discard at 0.1 and face-sorted alpha blending approximate static materials.

Block materials currently offer explicitly selected textures across the whole model; permutation conditions and material routing are not evaluated. Missing assets yield neutral geometry/explanations; multiple bindings require selection. TGA, per-face UV rotation, polygon/texture meshes, subpack overrides, unrelated third-party packs and built-in block shapes remain follow-ups. Animation, dynamic render controllers, visibility, block/item transforms and advanced material parity are excluded. Intersecting translucent faces can sort incorrectly. The existing Molang layer remains the sole authoring implementation.

The Three.js Texture/OrbitControls approach was researched, but automatic approval review rejected downloading its dependency because it interpreted the user's install restriction as including npm dependencies. No dependency was added; the local WebGL implementation requires none.

# Render-controller texture inference — October 27, 2026

Static structural matching reuses the existing Molang lexer/syntax checker and resource-subpack controller view. It enumerates direct aliases, ternaries and nested arrays, applies literal index truncation/clamping/wrapping, and correlates identical stable conditions/selectors. It never evaluates runtime queries, assignments, scripts or random calls. Different selectors and array lengths retain uncertainty. Unknown branches, missing aliases/controllers, duplicate definitions and layered textures cannot produce a conclusive preference. All owner textures remain selectable; explicit texture-file opens win. Automatic selections recompute on save; manual/neutral selections persist.

Official conventions: [render controller resources](https://mojang.github.io/bedrock-samples/Animations.html), [Molang resource arrays and indexing](https://mojang.github.io/bedrock-samples/Molang.html). This is bounded resource inference, not a second Molang evaluator.

## Controller-driven appearance, TGA and fractional box UVs — October 27, 2026 (0.26.7)

The remaining bull/pellet holes came from fractional box UV extents. Box atlas dimensions now use whole texels while geometry stays fractional; explicit per-face UV sizes stay fractional. A read-only atlas audit sampled all bull horn variants (3,000 interior points) and the slingshot pellet (150 points), finding zero transparent texels after correction. Evidence: `.test-temp/appearance-uv-audit.json`. The 141 copied appearance fixture source hashes were verified unchanged.

Render controllers now own normal appearance selection. The UI groups by owner, offers only branch-relevant synced inputs, and puts raw geometry/texture selection behind a manual inspection checkbox. Unknown runtime geometry/texture branches require one constrained controller variant, rather than drawing alternatives together; unresolved controller activation offers an explicit inactive choice. Unsupported partial branches and duplicate files cannot become conclusive render passes. These are static resource possibilities under valid property domains, not guarantees that behavior events can reach every state combination in-game.

Bounded constant folding handles literal property-derived array indices, including koi palette offsets. Reachable input discovery hides adult controls for egg/fry, hides patterns for wild coloration, and hides the palette of a disabled pattern. Hidden values persist until reset. Existing lexer/syntax/resource-binding assistance is reused without changing Molang files or executing scripts/runtime queries.

TGA decoding supports raw/RLE true-color (24/32-bit) and grayscale (8/16-bit), origin flips and alpha, with dimension/pixel/packet bounds and PNG conversion only in memory. Unsupported palette-mapped, 16-bit true-color and interleaved encodings report errors. Separate single-texture controller passes retain declaration order, alpha cutouts, independent bone visibility and nearest-neighbor textures. Fully transparent TGA passes are skipped so invisible adult overlays cannot distort an egg camera. Arbitrary multi-sampler material routing, custom shaders and fractional-alpha material parity remain unsupported.
